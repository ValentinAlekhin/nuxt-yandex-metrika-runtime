# Правила разработки

`nuxt-yandex-metrika-runtime` — независимый модуль Nuxt 4 для Яндекс Метрики. Настройки задаются
через Nuxt config, публичный runtime config и `useYandexMetrika()` во время работы приложения.
Сохраняй переносимость: пакет не должен зависеть от конкретного приложения, CMS или хранилища.

## Язык и инструменты

- Документация, описания коммитов и релизов — на русском. Исходный код, комментарии,
  тесты и технические сообщения — на английском. Используй стандартные английские ошибки Zod.
- Коммиты — по Conventional Commits с русским описанием, например
  `fix(runtime): отменить запуск счётчика после остановки`. Порядок работы и релизов —
  в [CONTRIBUTING.md](CONTRIBUTING.md).
- Используй Node из `.nvmrc` и npm с существующим `package-lock.json`.
- Все shell-команды запускай через `rtk`, неподдерживаемые команды — через `rtk proxy`.
  Если доступен `~/.codex/RTK.md`, прочитай его перед работой.
- Для управления интерфейсом десктопных приложений используй Peekaboo через `rtk peekaboo`.
  Работа с файлами и специализированными API/CLI допускается отдельно.
- Стиль задают Oxfmt и Oxlint: 2 пробела, одинарные кавычки, без точек с запятой
  и завершающих запятых, ширина 100, LF. Не добавляй зависимости и абстракции без необходимости.

## Устройство пакета

- `src/module.ts` — регистрация Nuxt-плагинов, автоимпорт composable и публичные типы.
- `src/runtime/config.ts`, `types.ts` — схемы Zod, нормализация и контракты.
- `src/runtime/controller.ts` — жизненный цикл счётчика без зависимости от Nuxt API.
- `src/runtime/loader.ts` — загрузка SDK и ожидание готовности счётчика.
- `src/runtime/plugin.client.ts`, `plugin.server.ts`, `state.ts` — адаптеры Nuxt, SSR и просмотры.
- `src/runtime/composables/useYandexMetrika.ts` — доступ к общему контроллеру приложения.
- `tests/unit/`, `tests/nuxt/`, `tests/e2e/` — уровни тестирования; приложение для интеграции
  находится в `tests/fixtures/basic/`.

## Обязательные инварианты

- `enabled: false` сохраняет плагины в сборке и позволяет включить счётчик через API.
- Явный `runtimeConfig.public.yandexMetrika` приоритетнее настроек `yandexMetrika` в Nuxt config.
- `configure()` валидирует весь patch до применения, объединяет поля `options` и сохраняет
  `enabled`, если он не передан. Ошибочный patch не останавливает работающий счётчик.
- Смена ID или параметров инициализации вызывает `destruct` старого счётчика перед `init`
  нового. Повторные команды идемпотентны; при гонке побеждает последняя конфигурация.
- `stop()` отменяет ожидающие delay/init. Поздняя загрузка SDK не возобновляет счётчик.
  События до готовности и после остановки отбрасываются без последующего воспроизведения.
- SSR меняет только сериализуемую конфигурацию через `useState('yandex-metrika:config')`.
  Запросы изолированы; DOM, SDK, Promise и ошибки не попадают в серверный payload.
- Автоматический запуск происходит после монтирования клиента. SDK загружается один раз
  на документ с `https://mc.yandex.ru/metrika/tag.js`; готовность определяется событием
  `yacounter<ID>inited`.
- `defer: true` и `triggerEvent: true` принадлежат модулю и не принимаются в `options`.
  Автоматические просмотры отправляются после рендера с актуальными title/referer.
  Неудачные, повторные и hash-only переходы исключены; async-страницы ожидают `page:finish`.
- Изменение debug/delay/loadTimeout не переинициализирует работающий счётчик.
  Debug не выводит параметры событий или пользовательские данные.
- HTTP endpoint, хранение настроек, авторизация и рассылка изменений вкладкам принадлежат приложению.

## Проверки и публикация

После установки зависимостей и выбора Node из `.nvmrc`:

```sh
rtk npm ci
rtk npm run dev:prepare
rtk npm run test:install-browser
rtk npm test
rtk npm run typecheck
rtk npm run lint
rtk npm run format:check
```

`npm test` собирает пакет и запускает все проекты Vitest. Перед отдельными unit/Nuxt-тестами
нужен `dev:prepare`. E2E проверяют production-сборку модуля из `dist/`; SDK подменяется,
реальная аналитика не отправляется. Nuxt runtime и e2e используют разные buildDir.

Не коммить `node_modules`, `dist`, `.nuxt*`, `.output`, кеши и архивы пакета.
Перед публикацией проверь содержимое `npm pack --dry-run`. Релизы используют SemVer:
тег `vX.Y.Z` запускает проверки, публикацию в npm и создание GitHub Release.
Версия тега должна совпадать с `package.json` и `package-lock.json`.

Настоящий SDK, повторный init и остановка Вебвизора требуют отдельной проверки на тестовом
счётчике. `stop()` не отзывает отправленные данные и cookies, не удаляет SDK и `window.ym`.
Общая загрузка SDK сохраняет таймаут первого запуска. Управляемый ID должен принадлежать
модулю: одновременная инициализация того же ID другой интеграцией не поддерживается.
